# Test Checker

Markdown で書いた手動テストの仕様書を読み込み、各ケースの結果をチェックしていく macOS 14+ 向けアプリ。
[md-reader](https://github.com/akaitadaaki/md-reader) をベースにしており、SwiftUI とシステム WebKit だけで動く。

## 考え方

- **仕様書（1プロジェクト1ファイル）は純粋な GFM のチェックリスト**。アプリは読むだけで書き換えない。
- **結果は実施ごとに別ファイル**へ保存する（`<仕様書名>.results/<日時>-<担当者>.md`）。
  GFM テーブルなので GitHub 上でもそのまま読める。
- どちらも Git で管理すれば、誰がいつ何を確認したかが履歴になる。

## 仕様書のフォーマット

```markdown
---
project: ログイン機能
---

# ログイン

## 正常系

- [ ] LOGIN-001 正しいID/PWでログインできる
  - 手順: ログイン画面で `test@example.com` / `password` を入力して送信
  - 期待: ダッシュボードへ遷移する
- [ ] LOGIN-002 「ログイン状態を保持」で再訪時も維持される

## 異常系

- [ ] LOGIN-101 存在しないIDでエラー表示
```

| 要素 | 意味 |
|---|---|
| `- [ ] ...` / `- [x] ...` | 1行 = 1テストケース（`*`, `+` も可。チェック有無は無視） |
| 行頭の `LOGIN-001` 形式 | **ID（任意・推奨）**。`英字で始まる英数字-数字` を ID とみなす |
| 見出し `#`〜`######` | カテゴリ。一覧のグループ分けと、ID が無い場合のキーに使う |
| 直後のインデントされた箇条書き | 手順・期待などの補足。一覧に小さく表示する |
| front matter の `project` | プロジェクト名（表示用） |

結果との突き合わせキーは **ID があれば ID、無ければ「見出しパス/タイトル」**。
ID が無いケースはタイトルを直すと過去の結果と紐付かなくなるので、ID を付けることを勧める。
コードブロック内のタスク行は無視する。

## 結果ファイルのフォーマット

```markdown
---
spec: login.md
tester: akai
started: 2026-08-23T09:30:00Z
---

| ID | 状態 | 確認日時 | メモ |
|---|---|---|---|
| LOGIN-001 | PASS | 2026-08-23 18:32 | |
| LOGIN-002 | FAIL | 2026-08-23 18:35 | 500エラー #123 |
| LOGIN-101 | RECHECK | 2026-08-23 18:40 | 環境差かも |
```

- 状態は `PASS` / `FAIL` / `SKIP` / `RECHECK`（要再確認）。未実施のケースは行を持たない。
- 確認日時はローカル時刻（`started` のみ UTC の ISO 8601）。
- 状態やメモを変えるたびに自動保存する。同じ分に同じ担当者が New Run した場合は `-2`, `-3` と連番を付ける。

## 使い方

詳しい手順（仕様書の作り方、担当者名の設定、実施の切り替え、名前の変更など）は **[docs/USAGE.md](docs/USAGE.md)** を参照。

```bash
make test    # コアのテスト
make run     # 開発実行
make app     # TestChecker.app を作って開く
```

1. ⌘O で仕様書（`.md`）を開く。Finder からドロップしてもよい。
2. 左ペインの丸アイコンを押して状態を選ぶ。最初の操作で結果ファイルが自動作成される。
   既に結果ファイルがある場合は最新のものを開く。
3. ツールバーの **New Run** で新しい実施を始める。ヘッダのメニューで過去の実施に切り替えられる。
4. 行をクリックすると、エディタとプレビューが該当行へスクロールする。

中央のエディタで仕様書を編集・保存（⌘S）でき、右ペインにプレビューが出る。検索は ⌘F。

## 構成

- `TestCheckerCore` — 仕様書パーサ・結果ファイル・集計・Markdown 変換・検索（テスト対象）
- `TestChecker` — チェックリスト / エディタ / プレビューの3ペイン UI
- `examples/login.md` — サンプル仕様書
