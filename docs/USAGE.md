# Test Checker 利用ガイド

手動テストの項目を Markdown に書き、アプリで1件ずつ結果（PASS / FAIL / SKIP / 要再確認）を付けていくツールです。
このガイドでは「初めて使う」ところから順に説明します。

---

## 1. アプリを起動する

```bash
cd test-checker
make app
```

`TestChecker.app` が作られて起動します。2回目以降は Finder で `TestChecker.app` をダブルクリックするだけで構いません
（`/Applications` に移動しても動きます）。

起動直後は「最近開いたファイル」の一覧か、空のウィンドウが表示されます。

---

## 2. テスト仕様書（md ファイル）を作る

テスト仕様書は **プロジェクトごとに1つの Markdown ファイル** です。好きなエディタで作成してください。
アプリ内の中央ペインでも編集・保存（⌘S）できます。

### 最小の例

```markdown
---
project: 会員登録機能
---

# 会員登録

## 正常系

- [ ] REG-001 必須項目を全て入力すると登録できる
  - 手順: 登録フォームに氏名・メール・パスワードを入力して「登録」を押す
  - 期待: 完了画面が表示され、確認メールが届く
- [ ] REG-002 登録後に自動でログイン状態になる

## 異常系

- [ ] REG-101 メールアドレスが不正な形式だとエラーが出る
- [ ] REG-102 既に登録済みのメールだとエラーが出る
```

これを `signup.md` のような名前で保存します。**ファイル名は自由**です。

### 書き方のルール

| 書くもの | 書き方 | 備考 |
|---|---|---|
| プロジェクト名 | 先頭の `---` で囲んだ中に `project: 名前` | 左ペインの見出しに表示される。省略するとファイル名が出る |
| カテゴリ | `#` `##` などの見出し | 左ペインでグループ分けされる。何階層でも可 |
| テストケース | `- [ ] ID タイトル` | **1行 = 1件**。`[ ]` の中は空でも `x` でも構わない（アプリは見ない） |
| ID | 行頭の `REG-001` のような `英字-数字` | **任意だが推奨**（理由は下記） |
| 手順・期待 | ケースの直下にインデントして `- 手順: ...` `- 期待: ...` | 自由記述。左ペインに小さく表示される。無くてもよい |

補足:

- 行頭が `-` 以外に `*` や `+` でも構いません。
- `- [ ]` で始まらない箇条書き（例: `- 補足メモ`）はテストケースとして扱われません。
- コードブロック（```）の中に書いた `- [ ]` は無視されます。

### なぜ ID を付けるのか

結果ファイルはケースを **ID で記録**します。ID が無いケースは「見出し / タイトル」で記録されるため、
後からタイトルの文言を直すと過去の結果と紐付かなくなります。ID があれば文言を自由に直せます。

ID の形式は `英字で始まる英数字` + `-` + `数字` です（例: `LOGIN-1`, `API_V2-010`）。
見出しごとに接頭辞を変えると管理しやすくなります。

### サンプル

リポジトリの [`examples/login.md`](../examples/login.md) がそのまま使えるサンプルです。コピーして書き換えてください。

## 3. 仕様書を開く

次のいずれかで開きます。

- ⌘O でファイル選択ダイアログから選ぶ
- Finder から md ファイルをウィンドウにドラッグ＆ドロップ
- 起動直後の「最近開いたファイル」から選ぶ

開くと画面が左右に分かれます。

```
┌──────────────┬────────────────┐
│ チェックリスト │ プレビュー       │
│ (結果を付ける) │ (読みやすい表示) │
└──────────────┴────────────────┘
```

仕様書の原文を編集したいときは、ツールバーの **鉛筆アイコン（✎）** を押すと中央に編集エリアが現れます
（もう一度押すと隠れます。起動時は非表示です）。編集して ⌘S で保存すると左右に即反映されます。

左のチェックリストに、仕様書から読み取ったテストケースが見出しごとに並びます。
「テストケースがありません」と出る場合は、`- [ ]` の書き方を見直してください（上のルール参照）。

---

## 4. 担当者名を設定する

左ペイン右上の **「担当者」欄** に自分の名前を入力します（例: `akai`）。

- 最初は Mac のユーザーのフルネームが入っています。
- 一度入力すると記憶され、次回以降も同じ名前が使われます。
- この名前は **結果ファイルのファイル名と中身** に使われます。**結果を付け始める前に設定してください**
  （途中で変えても、すでに作られた結果ファイルの名前は変わりません）。

---

## 5. 結果を付ける

1. 左ペインで、ケースの左にある **丸いアイコン** をクリックします。
2. メニューから状態を選びます。

   | 状態 | 意味 | アイコン |
   |---|---|---|
   | PASS | 期待どおり動いた | 緑のチェック |
   | FAIL | 期待と違った・バグ | 赤のバツ |
   | SKIP | 今回は対象外・実施しない | グレーのマイナス |
   | 要再確認 | 判断がつかない・環境を変えて再確認したい | オレンジの ? |
   | 未実施 | 元に戻す | 空の丸 |

3. 状態を付けると **メモ欄** が出ます。FAIL の理由や Issue 番号などを書いてください。
4. 保存操作は不要です。**状態やメモを変えるたびに自動で結果ファイルに保存**されます。

ケースの行（タイトル部分）をクリックすると、中央と右のペインがその行までスクロールします。
手順や期待を詳しく見たいときに使ってください。

上部の **進捗バー** に PASS / FAIL / 要再確認 / SKIP / 未実施 の件数が出ます。

その下の **絞り込みバー** で一覧を絞り込めます。「すべて」と各状態アイコン（未実施 / PASS / FAIL / SKIP / 要再確認）の6択で、
たとえば「FAIL だけ見直す」「未実施の残りを消化する」といった使い方ができます。

---

## 6. 結果ファイルはどこにできるか

仕様書と同じフォルダに、`仕様書名.results` というフォルダが作られ、その中に保存されます。

```
project/
├── signup.md                          ← 仕様書
└── signup.results/
    ├── 20260823-1830-akai.md          ← 8/23 18:30 に akai が開始した実施
    └── 20260901-1000-suzuki.md        ← 9/1 10:00 に suzuki が開始した実施
```

最初に状態を付けた瞬間に自動で作られます。中身は普通の Markdown の表なので、GitHub 上でもそのまま読めます。

```markdown
---
spec: signup.md
tester: akai
started: 2026-08-23T09:30:00Z
---

| ID | 状態 | 確認日時 | メモ |
|---|---|---|---|
| REG-001 | PASS | 2026-08-23 18:32 | |
| REG-101 | FAIL | 2026-08-23 18:35 | 全角@でも通ってしまう #42 |
```

仕様書と結果フォルダをまとめて Git にコミットしておけば、「誰が・いつ・何を確認したか」が履歴として残ります。

## 7. 実施（結果ファイル）を使い分ける

**1回のテスト実施 = 1つの結果ファイル** です。

- **新しい実施を始める**: ツールバーの **New Run** を押します。空の結果ファイルが新しく作られ、全ケースが未実施に戻ります。
  リリースごと・環境ごとにやり直すときに使います。
- **過去の実施を見る／続きをやる**: 左ペイン上部の **ファイル名（📄 アイコン）** をクリックすると一覧が出るので選びます。
- 仕様書を開いたときは、**一番新しい結果ファイルが自動で開かれます**。

同じ分に同じ担当者が New Run を2回押した場合は、`-2`, `-3` と連番が付き、上書きされません。

---

## 8. 名前を変えたいとき

### 仕様書のファイル名を変える

Finder などでファイル名を変えたら、**結果フォルダも同じ名前に変えてください**。

```
signup.md           → member-signup.md
signup.results/     → member-signup.results/
```

結果フォルダの名前が合っていないと、過去の結果が見つからず「未開始」扱いになります。
（結果ファイルの中の `spec:` 行は表示用なので、そのままでも動作に影響しません。）

### プロジェクト名（画面の見出し）を変える

仕様書先頭の `project:` を書き換えて保存するだけです。

### 担当者名を変える

左ペインの「担当者」欄を書き換えます。**次に New Run したときから** 新しい名前が使われます。
すでにある結果ファイルの名前を変えたい場合は、Finder で `日時-名前.md` の名前部分を直し、
ファイル内の `tester:` も合わせて書き換えてください。

### テストケースのタイトルを変える

ID を付けてあれば、タイトルは自由に書き換えて構いません。
ID が無いケースはタイトルがキーになっているので、書き換えると結果との紐付けが切れます
（結果ファイルの該当行の ID 列を新しいタイトルに書き換えれば復旧できます）。

## 9. よくある疑問

**Q. ケースを追加・削除したら？**
仕様書を保存すれば左ペインに即反映されます。削除したケースの結果は結果ファイルに残りますが、集計には含まれません。

**Q. 結果ファイルを手で編集してもいい？**
構いません。表の形式（4列、状態は `PASS` / `FAIL` / `SKIP` / `RECHECK`、日時は `yyyy-MM-dd HH:mm`）を守ってください。
形式が崩れるとそのファイルは読めなくなり、エラーが表示されます。

**Q. 複数人で同時にテストするには？**
担当者ごとに New Run して別ファイルにするのが前提です。同じ結果ファイルを同時に編集することは想定していません。

**Q. 仕様書を保存せずにチェックしようとするとエラーが出る**
結果ファイルは仕様書と同じ場所に作られるため、仕様書が未保存（Untitled）だと置き場所が決まりません。先に ⌘S で保存してください。

**Q. 検索したい**
⌘F で原文を検索できます（編集エリアが非表示でもプレビュー上でハイライトされます）。⌘G で次へ、⇧⌘G で前へ。

|---|---|
| 開く | ⌘O |

| 検索 | ⌘F |
| 次を検索 / 前を検索 | ⌘G / ⇧⌘G |
